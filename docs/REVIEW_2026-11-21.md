# Code review of harvey-netcode, 21 Nov 2026

**Status:** Current · **Last updated:** 2026-11-21

Static review of all C# under `Assets/_Project/Scripts/`, `Assets/_Project/Editor/`, `Assets/_Project/UI/Glass/`, and `Assets/_Project/Plugins/FishySteamworks/` on branch `harvey-netcode` (`d74a27e`), excluding edits to the 17 pre-existing dirty files.

## Worst first

1. **Pooled pickups carry stale state across a rematch (`ITM-17`).** `Pickup`, `FireExtinguisher`, `WetFloorSign`, and `GrenadeCase` do not reset their SyncVars in `OnStartServer`, so a tower rebuild can respawn items still marked away, empty, venting, placed, or armed.
2. **Starting a match from the Esc menu leaves the lobby in reception state (`INT-1`) and can trap the host's cursor (`LOB-9`).** `LobbyRunFlow` never sets `LobbyRoster._runInProgress` on `Countdown`, and `LobbyHostControls` does not close when a run starts or when disabled.
3. **Switchboard prop stream can overshoot its byte/heal budget (`SB-1`, `SB-2`) and re-derives tower floor count (`SB-3`).**
4. **Editor tools overwrite scenes, sign assets, or kit glass prefabs without §4 guards (`ED-9`, `ED-10`, `ED-11`).**
5. **Host accepts any Steam P2P connection under the player cap (`NET-2`, carried forward).** Open design/security call for Adam; already listed under Release risks in [WORKBOARD.md](WORKBOARD.md).
