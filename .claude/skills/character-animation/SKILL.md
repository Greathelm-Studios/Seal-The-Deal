# Character animation for game engines

Everything runs through `scripts/ca.mjs` (Node 18+) which finds Blender and runs the Blender scripts headless. Run it from anywhere; paths below are relative to this skill folder. Every command is non-interactive and exits non-zero on failure.

If you were not told this skill folder's path (Saber's `load_skill` gives only the name), it is the first of these that contains `scripts/ca.mjs`: `$CHARACTER_ANIMATION_SKILL`, `~/.saber/skills/character-animation`, `~/.agents/skills/character-animation`, `~/.claude/skills/character-animation`. Run the scripts by that full path; in Saber, read the reference files with `load_skill` and `file`.

Clip library: Quaternius Universal Animation Library 1 and 2 (CC0, 86 clips, 30 fps, UE-mannequin bone names) in the cache folder, `~/.cache/character-animation` unless `CHARACTER_ANIMATION_CACHE` is set. If `node scripts/ca.mjs search idle` says there is no catalogue, run setup first (see New computer).

## Workflow

1. **Inspect the character.** `node scripts/ca.mjs inspect <character.fbx|glb>` reports the skeleton, rig type, height, facing, rest pose (T or A) and the bone mapping. Exit code 2 means required bones are missing: it lists them. Write a map file for those (see [rigs and retargeting](references/rigs-and-retargeting.md)) and pass `--map`. Do not retarget a character that fails inspection.
2. **Find clips.** `node scripts/ca.mjs search walk`, `search attack --tag melee`, `search idle --loop`. Each line gives name, pack, duration, frames, loop or once, root-motion speed and tags. The catalogue is `<cache>/catalogue.json` if you need to filter further.
3. **Retarget.** `node scripts/ca.mjs retarget --character <file> --clips Idle_Loop,Walk_Loop,Jog_Fwd_Loop --out <dir>/work.blend`
   - In place is the default (the library's in-place variants). Add `--root-motion` for clips that should move the character (locomotion with root motion in Unreal, jumps that leave the ground). Jump clips need `--root-motion`: their in-place variants lose the vertical lift and the feet go through the floor.
   - `--fps 60` resamples by time. `--map map.json` overrides the bone map. Extra objects in the character file (lights, props) are dropped and listed.
   - `--add-to <dir>/work.blend` (instead of `--character`) adds clips to an existing work file, so library clips, AI clips and other packs (`--source`) end up in one file that `edit` can combine and `export` writes as one moveset. It keeps the file's frame rate and bone map, saves in place unless `--out` is given, and refuses a clip name already in the file unless `--replace` is passed.
4. **Preview and look.** `node scripts/ca.mjs preview --file <dir>/work.blend --out <dir>/preview` writes `<clip>_sheet.png` per clip: a three-quarter front row and a left side row over 6 frames, on a checker floor at the character's rest ground. Read the PNGs yourself. Check: no stretched or exploded limbs, not stuck in a T-pose, feet on the floor when they should be, facing the travel direction. The printed numbers back this up (lowest point above floor per frame, arm angle, hip turn, root-motion travel and its direction). Add `--mp4` for a video (`--follow` keeps a root-motion clip in frame), `--first-person` for a row seen from the eyes (first-person games), and `--prop sword.glb --hand r --prop-rotate left:90` to check a weapon clip with the weapon in hand. If something looks wrong, see [troubleshooting](references/rigs-and-retargeting.md#troubleshooting) before exporting.
   **Edit (optional).** When no clip fits as is, make one from the clips in the work file before reaching for the AI route: `node scripts/ca.mjs edit --blend <dir>/work.blend <operation>` with `trim`, `retime`, `mirror`, `transition` (A into B), `layer` (one clip's upper body or any bone subtree over another), `pose` (turn or move a bone over a frame range, optionally keeping the feet planted), `loop`, `foot-lock`, `hold` (one frame held still, such as a death's end pose), `ik` (move a hand or foot, or pin it in place), `delay` (bones arriving late, follow-through), `exaggerate` (more or less motion on chosen bones), `aim` (head looks at a point), `directions` (eight strafe or facing clips from one forward walk or run, for blend spaces) or `style` (stroll, brisk, heavy, sneak or your own settings on a walk). `edit ... list` shows the clips. Source clips are never changed; the new clip joins the file for preview and export. Read [editing](references/editing.md) for the options, axes and recipes, and preview every edited clip.
5. **Export.** `node scripts/ca.mjs export --blend <dir>/work.blend --engine unreal|unity|godot --out <dir>/export-unreal [--split]`. Unreal and Unity get FBX, Godot gets GLB; `--split` writes one file per clip instead of one bundled file. `--no-mesh` leaves the mesh out (clips for a character already in the engine); `--mesh-only` writes the character in its rest pose with no clips. `--bone-names ue|mixamo|cc` renames the mapped bones to Unreal mannequin, Mixamo or Character Creator names in the exported files, so engine retargeting tools that match by name map them automatically. Settings and engine import steps are in [engine presets](references/engine-presets.md).
6. **Verify the export.** `node scripts/ca.mjs verify --manifest <dir>/export-unreal/manifest.json` reopens every exported file in a fresh Blender and checks clip names, frame counts, bone names and bone positions against the working file. Then preview the exported file itself (`preview --file <export>.fbx`) and look at one sheet.
7. **Report** the export paths, the clips with durations and loop or root-motion choice, the preview sheets you checked and what you saw, and anything that failed inspection or looked off.

## When the library has no fitting clip

First check whether an edit of library clips covers it (see step 4). If not, say so, list the closest library clips, and offer the AI route: text-to-motion through the Uthana API, which costs money per second generated. Never spend without the user's explicit approval of the estimated cost. `node scripts/ca.mjs ai --prompt "..." --length 4` is a dry run that prints the cost; `--confirm-spend` makes the call. The downloaded GLB then goes through steps 1 to 6 with `retarget --source <file.glb> --clips all`, plus `--add-to <work.blend>` to put it beside library clips already retargeted. This route is untested; read [AI route](references/ai-route.md) first.

Any other animated FBX or GLB (for example another CC0 pack) works the same way with `--source`.

## New computer

1. Copy or clone this skill folder. Nothing in it is machine-specific.
2. Install Blender 4.5 LTS or 5.2 LTS. Both are tested (4.5.14 and 5.2.2, with identical results); 4.4, 5.0 and 5.1 should work but are untested, and older versions do not. Windows: `winget install --id BlenderFoundation.Blender`. macOS: `brew install --cask blender` or the blender.org installer. Linux: the distro package, snap or the blender.org tarball. If Blender is somewhere unusual, set `BLENDER_PATH` to the executable. `node scripts/ca.mjs blender` shows which one will be used.
3. Install Node 18 or newer if missing.
4. For Saber, which does not follow links, put a real copy in `~/.saber/skills/character-animation` (Saber's "Import Skills from Claude Code and Codex" does this, and never overwrites one already there, so delete the old copy first when updating). Saber's "Confine commands" setting blocks Blender and the cache folder, so leave it off for animation work.
5. Run `node scripts/ca.mjs setup`. It downloads both library packs (about 35 MB) from itch.io's free download path, unpacks them into the cache and builds the catalogue. Add `--test-character` to also fetch a CC0 test character on a different rig. It never prompts and is safe to re-run (it skips packs already present; `--force` refetches).

Sources and licences are in [library](references/library.md).
